## 3. Постановка задачі

Один запис ветеринарної клініки має формат:

```text
animal:String;species:String;visitType:String;price:double;urgent:boolean
```

У CSV-файлі типи не записуються, тому фактичний рядок має вигляд:

```text
Мурка;кіт;огляд;350.00;false
```

Поля:

- `animal` — ім'я тварини;
- `species` — вид тварини;
- `visitType` — тип візиту;
- `price` — вартість візиту;
- `urgent` — ознака ургентного візиту.

Програма повинна обчислити:

1. кількість коректних записів;
2. середню вартість;
3. загальний виторг;
4. кількість ургентних візитів.

Некоректний запис не повинен завершувати роботу всієї програми. Для нього формується повідомлення з номером рядка та причиною помилки.

## 11. Відповіді на контрольні питання

### 1. Яке призначення файла pom.xml?

`pom.xml` описує Maven-проєкт: його координати, версію Java, залежності, плагіни та правила збирання.

### 2. Чим відрізняються фази test, verify і package у Maven?

`test` компілює та запускає тести.  
`package` додатково створює готовий пакет, наприклад JAR.  
`verify` виконує перевірки, прив'язані до відповідної фази, наприклад статичний аналіз.

### 3. Навіщо потрібен Maven Wrapper?

Maven Wrapper дозволяє запускати проєкт через визначену версію Maven без вимоги однакового глобального Maven на кожному комп'ютері.

### 4. Яку роль відіграє метод main?

`main` є точкою входу Java-програми. JVM починає виконання консольного застосунку саме з нього.

### 5. Чим примітивний тип відрізняється від String?

Примітивний тип зберігає просте значення, наприклад `int`, `double` або `boolean`. `String` є об'єктним типом для зберігання тексту.

### 6. Чому середнє потрібно обчислювати в double?

Середнє може бути дробовим. Використання `double` дозволяє не втратити дробову частину під час ділення.

### 7. Що станеться, якщо Integer.parseInt отримає "abc"?

Буде згенеровано `NumberFormatException`, тому неправильне числове значення потрібно перехопити й обробити.

### 8. Чому не можна мовчки пропускати рядок із помилкою?

Користувач повинен знати, який запис був відхилений і з якої причини. Інакше неправильні дані можуть залишитися непоміченими.

### 9. Як String.split(";", -1) обробляє порожнє останнє поле?

Параметр `-1` зберігає порожнє останнє поле в отриманому масиві, тому можна правильно визначити неправильну структуру запису.

### 10. Чому краще використовувати Path.of?

`Path.of` формує шлях незалежно від операційної системи і не вимагає вручну використовувати `\` або `/`.

### 11. Навіщо явно задавати StandardCharsets.UTF_8?

Це гарантує однакове кодування файла на різних операційних системах і правильну роботу з українськими символами.

### 12. Чим %n відрізняється від \n?

`%n` використовує системний роздільник рядків, тоді як `\n` безпосередньо означає символ переведення рядка LF.

### 13. Які дані потрібно перевірити у варіанті 21?

Потрібно перевірити:

- рівно п'ять полів;
- непорожні `animal`, `species`, `visitType`;
- числовий формат `price`;
- `price >= 0`;
- скінченність `price`;
- `urgent` повинен бути `true` або `false`.

### 14. Які тести виявлять помилку в обчисленні середнього?

Потрібен набір із кількох відомих значень, для яких середнє легко обчислити вручну. Також корисні випадки з одним записом та відсутністю коректних записів.

### 15. Яке призначення статичного аналізатора?

Статичний аналізатор перевіряє код без його звичайного виконання та допомагає знаходити потенційні дефекти і підозрілі конструкції.

### 16. Яку роль виконує GitHub Actions?

GitHub Actions автоматично запускає перевірки проєкту після змін у репозиторії та дозволяє перевірити збірку на різних операційних системах.

### 17. Що має містити GitHub Issue на дефект?

Issue має містити опис проблеми, кроки відтворення, очікуваний результат і фактичний результат.

### 18. Що потрібно вказати в розділі академічної доброчесності?

Потрібно вказати використаний інструмент ШІ, його ролі, основні запити, прийняті рекомендації, виправлені помилки, власний внесок і підтвердження розуміння коду.

### 19. Яку роботу виконує DevOps, а яку Валідатор?

DevOps відповідає за інфраструктуру проєкту: Maven, збірку, аналізатор, JAR і CI. Валідатор перевіряє коректність результатів, крайові випадки та допомагає знаходити дефекти.

### 20. Який рядок програми найскладніше пояснити і чому?

Один із найважливіших рядків:

```java
double averagePrice =
        validCount == 0 ? 0.0 : totalRevenue / validCount;
```

Він використовує тернарний оператор. Якщо коректних записів немає, повертається `0.0`, щоб уникнути ділення на нуль. Інакше загальний виторг ділиться на кількість коректних записів.

## 4. Клас-сутність VetVisit

Для представлення одного візиту створено клас `VetVisit`.

Клас містить поля:

```java
private final String animal;
private final String species;
private final String visitType;
private final double price;
private final boolean urgent;
```

Усі поля є `private`, тому зовнішній код не має прямого
доступу до внутрішнього стану об'єкта.

Поля також оголошені `final`, тому після завершення
конструктора їх значення не змінюються.

Конструктор перевіряє основні інваріанти:

- `animal` не може бути `null`, порожнім або складатися лише з пробілів;
- `species` не може бути `null`, порожнім або складатися лише з пробілів;
- `visitType` не може бути `null`, порожнім або складатися лише з пробілів;
- `price` не може бути від'ємним;
- `price` не може бути `NaN`;
- `price` не може бути нескінченністю.

Сеттери не використовуються.

Для читання стану передбачені методи доступу.

Метод `toString()` використовує `Locale.ROOT`,
щоб формат чисел не залежав від локальних налаштувань операційної системи.

## 5. Фабричний метод fromCsv і record PriceUrgency

Для створення `VetVisit` із CSV-рядка реалізовано статичний метод:

```java
VetVisit.fromCsv(line)
```

Метод:

- перевіряє, що рядок містить рівно п'ять полів;
- перетворює поле `price` у `double`;
- перевіряє поле `urgent`;
- викликає конструктор `VetVisit`;
- повідомляє про помилкові значення через `IllegalArgumentException`.

Номер рядка CSV не передається до `VetVisit`.
Його додає цикл читання у `Main`, тому клас предметної області
не залежить від конкретного файла.

Для представлення підсумку створено:

```java
public record PriceUrgency(double totalPrice, int urgentCount)
```

`PriceUrgency` зберігає:

- загальну вартість коректних візитів;
- кількість термінових візитів.

Record перевіряє, що загальна вартість є скінченною
і невід'ємною, а кількість термінових візитів не є від'ємною.

## 11. Відповіді на контрольні питання

### 1. Яку проблему розв'язує клас-сутність порівняно з рядком і паралельними змінними?

Клас-сутність об'єднує пов'язані дані та правила їх
коректності в одному типі. Це зменшує ризик переплутати
поля або працювати з частково перевіреним записом.

### 2. Що означають private і final у полях класу?

`private` забороняє прямий доступ до поля ззовні класу.
`final` означає, що після присвоєння в конструкторі посилання
або значення поля не можна змінити.

### 3. Що таке інкапсуляція і яку проблему вона запобігає?

Інкапсуляція приховує внутрішній стан об'єкта та дозволяє
керувати доступом до нього через визначений інтерфейс.
Вона запобігає довільній зміні полів із зовнішнього коду.

### 4. Чому перевірку інваріантів розміщують у конструкторі?

Щоб неможливо було створити об'єкт у некоректному стані.

### 5. Чим Objects.requireNonNull відрізняється від isBlank?

`Objects.requireNonNull` перевіряє, чи посилання не дорівнює
`null`, а `isBlank()` перевіряє, чи рядок не є порожнім
або складеним лише з пробільних символів.

### 6. Чому відсутність сеттерів допомагає зберегти коректний стан?

Після успішної перевірки в конструкторі зовнішній код
не може змінити поле на некоректне значення.

### 7. Які методи й властивості автоматично отримує record?

Record автоматично отримує компоненти, методи доступу до них,
`equals`, `hashCode`, `toString` і канонічний конструктор.

### 8. Чим record відрізняється від звичайного класу-сутності?

Record призначений переважно для компактного представлення
набору значень і автоматично створює стандартні методи.
Звичайний клас дає більше свободи для власної структури
і поведінки.

### 9. Чому record не гарантує глибоку незмінність змінного списку?

Якщо компонент record містить посилання на змінний об'єкт,
наприклад `List`, сам вміст цього об'єкта може бути змінений.

### 10. Для чого потрібен статичний фабричний метод fromCsv?

Він приховує логіку перетворення текстового CSV-рядка
на коректний об'єкт предметної області.

### 11. Де потрібно перехоплювати помилку розбору одного рядка?

На рівні циклу читання рядків, щоб один неправильний запис
не завершував обробку всього файла.

### 12. Чому неправильний запис не можна додавати до списку до завершення перевірки?

Інакше некоректні дані можуть потрапити до статистики
та спотворити результат.

### 13. Яке призначення toString і чому він не замінює формат CSV?

`toString()` створює зручне текстове представлення об'єкта
для людини та налагодження. Формат CSV має окремі правила
і може використовуватися для машинного обміну даними.

### 14. Навіщо використовувати Locale.ROOT у toString і звіті?

Щоб формат чисел не залежав від локалі конкретної
операційної системи.

### 15. Що означає схема тесту AAA?

AAA означає Arrange, Act, Assert:
підготовка даних, виконання дії та перевірка результату.

### 16. Які негативні випадки потрібно перевірити для конструктора?

Потрібно перевірити `null`, порожні текстові значення,
від'ємні числа, `NaN`, нескінченність та інші значення,
що порушують інваріанти класу.

### 17. Як довести, що рефакторинг не змінив зовнішню поведінку попередньої роботи?

Запустити старі тести та порівняти звіт на тому самому
контрольному вхідному файлі до і після рефакторингу.

### 18. Чому тести попередньої роботи мають проходити після цієї роботи?

Вони є регресійними тестами та підтверджують, що нові зміни
не зламали вже реалізовану функціональність.

### 19. Які файли інфраструктури переносяться з попередньої роботи без повторного створення?

`pom.xml`, Maven Wrapper, GitHub Actions workflow,
структура Maven-проєкту та попередні тести.

### 20. Який рядок реалізації найкраще демонструє інкапсуляцію і чому?

Наприклад:

```java
private final double price;
```

Поле приховане від прямої зміни зовнішнім кодом,
а його коректність контролює конструктор класу.
