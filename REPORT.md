## 3. Постановка задачі

Один запис ветеринарної клініки має формат:

```text
animal:String;species:String;visitType:String;price:double;urgent:boolean
```

У CSV-файлі типи не записуються, тому фактичний рядок має вигляд:

```text
Мурка;кіт;огляд;350.00;false
```

Поля:

- `animal` — ім'я тварини;
- `species` — вид тварини;
- `visitType` — тип візиту;
- `price` — вартість візиту;
- `urgent` — ознака ургентного візиту.

Програма повинна обчислити:

1. кількість коректних записів;
2. середню вартість;
3. загальний виторг;
4. кількість ургентних візитів.

Некоректний запис не повинен завершувати роботу всієї програми. Для нього формується повідомлення з номером рядка та причиною помилки.

## 11. Відповіді на контрольні питання

### 1. Яке призначення файла pom.xml?

`pom.xml` описує Maven-проєкт: його координати, версію Java, залежності, плагіни та правила збирання.

### 2. Чим відрізняються фази test, verify і package у Maven?

`test` компілює та запускає тести.  
`package` додатково створює готовий пакет, наприклад JAR.  
`verify` виконує перевірки, прив'язані до відповідної фази, наприклад статичний аналіз.

### 3. Навіщо потрібен Maven Wrapper?

Maven Wrapper дозволяє запускати проєкт через визначену версію Maven без вимоги однакового глобального Maven на кожному комп'ютері.

### 4. Яку роль відіграє метод main?

`main` є точкою входу Java-програми. JVM починає виконання консольного застосунку саме з нього.

### 5. Чим примітивний тип відрізняється від String?

Примітивний тип зберігає просте значення, наприклад `int`, `double` або `boolean`. `String` є об'єктним типом для зберігання тексту.

### 6. Чому середнє потрібно обчислювати в double?

Середнє може бути дробовим. Використання `double` дозволяє не втратити дробову частину під час ділення.

### 7. Що станеться, якщо Integer.parseInt отримає "abc"?

Буде згенеровано `NumberFormatException`, тому неправильне числове значення потрібно перехопити й обробити.

### 8. Чому не можна мовчки пропускати рядок із помилкою?

Користувач повинен знати, який запис був відхилений і з якої причини. Інакше неправильні дані можуть залишитися непоміченими.

### 9. Як String.split(";", -1) обробляє порожнє останнє поле?

Параметр `-1` зберігає порожнє останнє поле в отриманому масиві, тому можна правильно визначити неправильну структуру запису.

### 10. Чому краще використовувати Path.of?

`Path.of` формує шлях незалежно від операційної системи і не вимагає вручну використовувати `\` або `/`.

### 11. Навіщо явно задавати StandardCharsets.UTF_8?

Це гарантує однакове кодування файла на різних операційних системах і правильну роботу з українськими символами.

### 12. Чим %n відрізняється від \n?

`%n` використовує системний роздільник рядків, тоді як `\n` безпосередньо означає символ переведення рядка LF.

### 13. Які дані потрібно перевірити у варіанті 21?

Потрібно перевірити:

- рівно п'ять полів;
- непорожні `animal`, `species`, `visitType`;
- числовий формат `price`;
- `price >= 0`;
- скінченність `price`;
- `urgent` повинен бути `true` або `false`.

### 14. Які тести виявлять помилку в обчисленні середнього?

Потрібен набір із кількох відомих значень, для яких середнє легко обчислити вручну. Також корисні випадки з одним записом та відсутністю коректних записів.

### 15. Яке призначення статичного аналізатора?

Статичний аналізатор перевіряє код без його звичайного виконання та допомагає знаходити потенційні дефекти і підозрілі конструкції.

### 16. Яку роль виконує GitHub Actions?

GitHub Actions автоматично запускає перевірки проєкту після змін у репозиторії та дозволяє перевірити збірку на різних операційних системах.

### 17. Що має містити GitHub Issue на дефект?

Issue має містити опис проблеми, кроки відтворення, очікуваний результат і фактичний результат.

### 18. Що потрібно вказати в розділі академічної доброчесності?

Потрібно вказати використаний інструмент ШІ, його ролі, основні запити, прийняті рекомендації, виправлені помилки, власний внесок і підтвердження розуміння коду.

### 19. Яку роботу виконує DevOps, а яку Валідатор?

DevOps відповідає за інфраструктуру проєкту: Maven, збірку, аналізатор, JAR і CI. Валідатор перевіряє коректність результатів, крайові випадки та допомагає знаходити дефекти.

### 20. Який рядок програми найскладніше пояснити і чому?

Один із найважливіших рядків:

```java
double averagePrice =
        validCount == 0 ? 0.0 : totalRevenue / validCount;
```

Він використовує тернарний оператор. Якщо коректних записів немає, повертається `0.0`, щоб уникнути ділення на нуль. Інакше загальний виторг ділиться на кількість коректних записів.

## 4. Клас-сутність VetVisit

Клас `VetVisit` представляє один візит до ветеринарної
клініки.

Він містить такі поля:

```java
private final String animal;
private final String species;
private final String visitType;
private final double price;
private final boolean urgent;
```

Використання `private` забезпечує інкапсуляцію та забороняє
прямий доступ до внутрішнього стану ззовні класу.

Використання `final` означає, що після завершення конструктора
значення полів не можуть бути переприсвоєні.

Setter-и у класі відсутні.

### Інваріанти VetVisit

Конструктор перевіряє:

- `animal` не є `null`, порожнім або blank;
- `species` не є `null`, порожнім або blank;
- `visitType` не є `null`, порожнім або blank;
- `price >= 0`;
- `price` є скінченним числом.

Для числової перевірки використовується:

```java
Double.isFinite(price)
```

Тому значення:

```text
NaN
Infinity
-Infinity
```

не допускаються.

У випадку порушення інваріанта конструктор генерує
`IllegalArgumentException`.

Метод `toString()` використовує `Locale.ROOT`, тому
форматування дробових чисел не залежить від локалі
операційної системи.

## 5. Фабричний метод fromCsv і record PriceUrgency

### VetVisit.fromCsv

Для перетворення CSV-рядка у готовий об'єкт використовується:

```java
VetVisit.fromCsv(String line)
```

Очікуваний формат:

```text
animal;species;visitType;price;urgent
```

Фабричний метод:

- перевіряє кількість полів;
- виконує числовий розбір `price`;
- перевіряє формат `urgent`;
- після розбору викликає конструктор `VetVisit`.

Таким чином `fromCsv` відповідає за структуру CSV,
а конструктор — за предметні інваріанти.

Номер рядка CSV залишається на рівні циклу читання у `Main`
і не є частиною предметної сутності.

### PriceUrgency

Для допоміжного результату створено record:

```java
public record PriceUrgency(
        double totalPrice,
        int urgentCount)
```

Компонент `totalPrice` зберігає загальну вартість коректних
візитів.

Компонент `urgentCount` зберігає кількість термінових візитів.

Record перевіряє, що:

- `totalPrice` є скінченним невід'ємним числом;
- `urgentCount >= 0`.

## 6. Інтеграція моделі у фактичну обробку

Після виправлення реалізації `Main` не виконує повторний
ручний розбір CSV.

Фактичний шлях обробки має вигляд:

```text
data/input.csv
        ↓
Files.readAllLines()
        ↓
VetVisit.fromCsv()
        ↓
конструктор VetVisit
        ↓
List<VetVisit>
        ↓
Main.calculateSummary()
        ↓
PriceUrgency
        ↓
формування звіту
```

У циклі читання використовується:

```java
try {
    VetVisit visit = VetVisit.fromCsv(line);
    visits.add(visit);
} catch (IllegalArgumentException exception) {
    errors.add(
            "Рядок " + lineNumber + ": "
                    + exception.getMessage());
}
```

Після завершення читання:

```java
PriceUrgency summary = Main.calculateSummary(visits);
```

Кількість коректних записів визначається безпосередньо
через:

```java
int validCount = visits.size();
```

Середня вартість обчислюється на основі:

```java
summary.totalPrice()
```

Таким чином `VetVisit.fromCsv`, `List<VetVisit>` та
`PriceUrgency` реально використовуються основною програмою,
а не існують лише як окремі допоміжні класи.

## 13. Відповіді на контрольні питання

### 1. Яку проблему розв'язує клас-сутність порівняно з рядком і паралельними змінними?

Клас-сутність об'єднує пов'язані дані та правила їх
коректності в одному типі та зменшує ризик переплутати
поля або працювати з частково перевіреним записом.

### 2. Що означають private і final у полях класу?

`private` приховує поле від прямого доступу ззовні класу,
а `final` забороняє повторне присвоєння після ініціалізації.

### 3. Що таке інкапсуляція?

Інкапсуляція приховує внутрішній стан об'єкта і дозволяє
контролювати роботу з ним через визначені методи.

### 4. Чому інваріанти перевіряються у конструкторі?

Це не дозволяє створити об'єкт предметної області
у некоректному стані.

### 5. Чим Objects.requireNonNull відрізняється від isBlank?

`Objects.requireNonNull` перевіряє відсутність `null`,
а `isBlank()` визначає, чи рядок порожній або містить лише
пробільні символи.

### 6. Чому відсутність setter-ів допомагає зберегти коректність?

Після успішного конструктора зовнішній код не може
довільно замінити перевірене значення на некоректне.

### 7. Що автоматично отримує record?

Record автоматично отримує методи доступу до компонентів,
`equals()`, `hashCode()`, `toString()` та канонічний
конструктор.

### 8. Чим record відрізняється від звичайного класу?

Record є компактною формою представлення набору значень,
тоді як звичайний клас дає більше свободи для власного
стану та поведінки.

### 9. Чому record не гарантує глибоку незмінність?

Якщо компонент record посилається на змінний об'єкт,
наприклад `List`, вміст цього об'єкта все ще можна змінити.

### 10. Для чого потрібен fromCsv?

`fromCsv` ізолює правила розбору CSV та перетворює один
текстовий рядок на готовий об'єкт предметної області.

### 11. Де потрібно перехоплювати помилку одного рядка?

На рівні циклу читання у `Main`, щоб одна помилка не
завершувала обробку всього файла.

### 12. Чому неправильний запис не додається до списку?

Інакше він міг би вплинути на статистичні показники.

### 13. Для чого використовується toString?

`toString()` створює стабільне текстове представлення
об'єкта, але не замінює окремий формат CSV.

### 14. Для чого Locale.ROOT?

`Locale.ROOT` забезпечує однакове форматування дробових
чисел незалежно від локалі операційної системи.

### 15. Що означає AAA у тестуванні?

Arrange — підготовка даних, Act — виконання дії,
Assert — перевірка результату.

### 16. Які негативні випадки потрібно перевірити?

`null`, blank-значення, від'ємні числа, `NaN`,
`Infinity`, неправильну кількість CSV-полів і неправильні
формати значень.

### 17. Як довести, що рефакторинг не змінив зовнішню поведінку?

Потрібно запустити старі тести та порівняти результат
на однаковому контрольному наборі даних до і після
рефакторингу.

### 18. Чому старі тести повинні проходити?

Вони виконують роль регресійних тестів і підтверджують,
що вже реалізована функціональність не була зламана.

### 19. Яка інфраструктура переноситься з LAB 01?

`pom.xml`, Maven Wrapper, GitHub Actions workflow,
попередні тести та структура Maven-проєкту.

### 20. Який фрагмент найкраще демонструє використання предметної моделі?

Наприклад:

```java
VetVisit visit = VetVisit.fromCsv(line);
visits.add(visit);
```

Цей код показує, що CSV-рядок реально перетворюється
на об'єкт `VetVisit`, який потім бере участь у подальшій
обробці програми.
